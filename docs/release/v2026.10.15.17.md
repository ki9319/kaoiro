# Release v2026.10.15.17

- Deployed: 2026-10-16 (server and runner; the server update started on 2026-10-15)
- Commit: `f3d8a8fe08361570bd7dbd820a81e93821ceb924`
- Previous production release: [v2026.10.15.9](v2026.10.15.9.md) (`e02506ac`, server and runner)
- Range: `v2026.10.15.9..v2026.10.15.17`, 11 commits
- Release class: TL (the Grok and Antigravity wrapper CLIs change how they apply a rename), plus a server update

## Highlights

- The server no longer accepts HTTP/2, which closes the exposure to a Bandit
  advisory that has no fixed release yet ([issue #663](https://github.com/sakuraiyuta/kaoiro/issues/663)).
- The dashboard timeline and peer headings show the directory display name
  with a small persona face ([issue #666](https://github.com/sakuraiyuta/kaoiro/issues/666)).
- Two new personas, shirogane and moegi ([issue #667](https://github.com/sakuraiyuta/kaoiro/issues/667)).
- After a dashboard rename, `list_agents` reports the new name on every engine
  ([issue #669](https://github.com/sakuraiyuta/kaoiro/issues/669)).

## Changes

### Server

- The Phoenix endpoint turns HTTP/2 off (`http_2_options: [enabled: false]`)
  until Bandit ships a fix for its HIGH advisory ([issue #663](https://github.com/sakuraiyuta/kaoiro/issues/663)).
  HTTP/1.1 and WebSocket upgrades are unchanged. The server README describes
  how to check and roll back.
- `list_agents` takes each agent's display name from the peer directory
  before the last live state, so a dashboard rename shows on the next read for
  every engine, including disconnected agents ([issue #669](https://github.com/sakuraiyuta/kaoiro/issues/669)).
  An invalid directory name is omitted rather than replaced by an older live
  name. See [Display-name authority](../reference/inter-agent/directory.md#display-name-authority).

### Dashboard

- Agent names in the response timeline, the inter-agent headings and both
  settings lists come from one resolver: the directory display name first,
  then the live display name, the live persona name, the directory persona
  name and the id ([issue #666](https://github.com/sakuraiyuta/kaoiro/issues/666)).
  Sprites still follow the live persona.
- Peer headings show a small persona face that follows the peer's state.

### Personas

- New bundled packs `shirogane` (silver, for Grok Build peers) and `moegi`
  (moegi green, for Claude Haiku peers), each with all eight states including
  `fatigued` ([issue #667](https://github.com/sakuraiyuta/kaoiro/issues/667)). See
  [Character-design policy](../specs/personas.md).

### Wrappers

- Grok Build applies `display_name_sync`; before, the CLI registered the
  rename callback under a name the server link never called ([issue #669](https://github.com/sakuraiyuta/kaoiro/issues/669)).
- Antigravity keeps the newest rename that arrives before its host exists and
  applies it once the host starts, as Claude Code and Codex already did. A
  rename right after launch is no longer lost.
- The Grok and Antigravity CLIs type-check their server-link callback options,
  so a misnamed callback fails the typecheck.

### Documentation

- `CLAUDE.md` and `AGENTS.md` are in English, and documents link issue numbers
  to their GitHub issues ([issue #668](https://github.com/sakuraiyuta/kaoiro/issues/668)).

## Upgrading

- No configuration change.
- Update the server and the runner to the same commit.
- The release is TL: follow the canary stage in
  [High-risk change release](../operations/high-risk-change-release.md).
- The new personas appear after the server update; launch an agent with
  `shirogane` or `moegi` to use them.

## Known issues

- With the persona face, a timeline heading row is as tall as the 2.25rem
  portrait, which stretches the bubble a little.
- Three name reads in `dashboard/src/App.svelte` still prefer the live name
  ([issue #670](https://github.com/sakuraiyuta/kaoiro/issues/670)).
