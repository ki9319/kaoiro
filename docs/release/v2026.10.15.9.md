# Release v2026.10.15.9

- Deployed: 2026-10-15 (server and runner)
- Commit: `e02506acf9b0d83f8fceba18f978cfc9b1932e14`
- Previous production release: v2026.10.15.4 (`e388c082`, runner only; the
  server was on v2026.10.14.13, `6e7f7b7b`)
- Range: `v2026.10.15.4..v2026.10.15.9`, 10 commits
- Release class: TL (wrapper behaviour, runner update)
- The server is updated only to bring server and runner back to the same
  commit. The range changes no server, dashboard or protocol code; from
  v2026.10.14.13 the server side changes one server test.

## Highlights

- Engine processes started by kaoiro can tell that they run under kaoiro
  (#659).
- A Codex peer with autonomous approval can reset its own session without an
  operator dialog (#661).
- Antigravity peers report rate limits right after they start, and Grok peers
  report their weekly allowance (#660).

## Changes

### All engines

- The wrapper exports `KAOIRO_AGENT` to native engine processes, tool shells
  and command hooks, on start and on resume (#659). It keeps the parent
  environment and each engine's own filtering. User-level settings can test
  for the variable to apply rules only to managed sessions. See
  [Wrapper configuration](../reference/configuration/wrapper.md).

### Codex

- `request_session_reset` follows the peer's approval policy (#661). When both
  the approval sent with the current turn and the latest selection are
  `never`, the call skips the operator dialog. A stricter
  selection still opens the dialog. The reset is still applied at the turn
  boundary, and the server can still refuse it. See
  [ADR-0043](../adr/0043-agent-initiated-session-reset.md) and
  [Session tools](../reference/inter-agent/session-tools.md).

### Antigravity

- The CLI probes `/usage` once right after the initial state, on fresh starts
  and on `--resume`, unless an initial prompt starts a turn (#660). Before, an
  Antigravity peer published no `rate_limits` until its first turn ended.

### Grok Build

- The wrapper reads the weekly account allowance through `_x.ai/billing` and
  publishes it as `rate_limits.seven_day` on `state_change` and `whoami`
  (#660). It publishes no `status` and no `five_hour` window. See
  [Account rate limits](../reference/engines/grok-acp.md#account-rate-limits)
  and the [evidence](../evidence/grok/2026-10-15-rate-limits.md).

## Upgrading

- No configuration change.
- Update the server and the runner to the same commit. This release also
  closes the gap left by v2026.10.15.4, which updated only the runner.
- The new `KAOIRO_AGENT` marker reaches a session only when it starts or
  resumes after the runner update.

## Known issues

- On develop CI, the Grok test `cli_rate_limits.test.ts` failed because it did
  not pass `PATH` to the Grok fixture. The test was fixed in `9e1ead1d`, after
  this commit. The fix changes only the test, so the release was not rebuilt.
- Codex agents do not have `request_compact` yet (#662).
- Follow-up tests for the Antigravity startup probe are tracked in #664.
