## Highlights

Grok Build reaches the same everyday use as the other engines when the
operator works with it directly:

- a resumed Grok agent keeps its session, cwd, permission, model and effort;
- the dashboard replays its history;
- the launch dialog lists Grok's models;
- model and effort can be switched while the agent runs, and the context
  usage is shown.

Engine contract: [Grok ACP](../reference/engines/grok-acp.md). Parity as a
delegated peer is work unit 5 (#628).

## Changes

### Grok Build engine

- Live model and effort switching through `session/set_config_option`, and
  context usage from the last model call (work unit 4, #593). An effort is
  checked against the model it will run with, including a model switch still
  in flight. A switch request that gets no answer within 15 seconds fails the
  agent instead of stalling its queue.
- Cold resume through `session/resume`, with the requested model and effort
  applied before the first prompt (work unit 3a, #644).
  - A model or effort that cannot be applied at resume is kept as the
    requested value, so the next resume tries it again. The session's actual
    model is shown as a fallback.
  - The runner discovers Grok sessions through ACP `session/list`.
  - Every probe process group is torn down within a bound when the agent
    stops, is superseded or the runner shuts down.
- Dashboard history on resume, rebuilt from Grok's session log with size,
  time and shape bounds (work unit 3b, #645).
- Launch catalog: the runner reads Grok's model list with an
  `initialize`-only probe after it registers, keeps the last good reading,
  and re-broadcasts it (work unit 3c, #646). For a few seconds after the
  runner starts, the launch dialog offers `default` only.
  - The committed tests pin that the catalog and session-list probes send no
    method beyond `initialize` and `session/list`.
  - That these probes attempt no model request is a dated measurement on
    Grok 1.0.52 ([evidence](../evidence/grok/2026-10-15-catalog-and-quota.md)).
- Streamed text chunks are joined into one assistant message, and an
  inter-agent turn no longer shows its wrapped prompt as a user message
  (#621).
- `result.text` is capped at 16 KiB, as on the other engines (#622).
- A `state_change` is published only when it differs from the last one (#623).
- The launch profile is not projected while the permission control is
  unknown (#620).
- Metadata of a session generation that is still loading is published when
  it is promoted, and Grok's replay during `session/load` is kept out of it
  (#633).

### All engines

- Text clipping cuts at UTF-8 character boundaries and no longer exceeds its
  byte cap (#624).

### Tests

- The live Grok tests answer permission requests through a test plugin hook,
  so they run on any host (#615).

## Upgrading

- No configuration change. Runners with the `grok` capability get the new
  behaviour after the runner update. The server does not need an update for
  this release.

## Known issues

- The dashboard's fallback hint uses Claude's safety-fallback wording for a
  Grok restore hold, and an effort hold is not visible in the dashboard
  (#649).
- History replay can keep a lone high surrogate at the exact 16 KiB join
  boundary (#653).
- Grok's built-in fallback model list cannot be told apart from a live one.
  The launch catalog shows the list as Grok reports it.
- Not yet supported on Grok: rate limit reporting, early delivery to a running
  turn, reply basis v1 and attachments (work unit 5, #628).
