# Release v2026.10.20.5

- Deployed: 2026-10-20 (server and runner)
- Commit: `a470e90b01a7de3fdc64c8905528e44818015960`
- Previous production release: [v2026.10.18.1](v2026.10.18.1.md) (`69b35ffd`, server and runner)
- Range: `v2026.10.18.1..v2026.10.20.5`, 47 commits
- Release class: TL (the Claude Code wrapper's notification parser, the
  Codex delivery gate and the runner's delivery settings change). The runner
  start path is unchanged.

## Highlights

- A Claude Code peer can call `send_to_agent` from a turn started by a
  `Monitor` notification again. Claude Code appends a PushNotification
  sentence to Monitor event notifications, and the wrapper refused the whole
  notification as malformed
  ([issue #697](https://github.com/sakuraiyuta/kaoiro/issues/697)).
- Codex operator steer is decided by the per-agent delivery policy and the
  host ceiling; the host-wide opt-in variables no longer gate it
  ([issue #563](https://github.com/sakuraiyuta/kaoiro/issues/563)).
- The server deploy CLI prints a recovery command that works from every
  persisted phase of an update or rollback
  ([issue #696](https://github.com/sakuraiyuta/kaoiro/issues/696)).

## Changes

### Wrappers

- Claude Code: the notification parser accepts the exact PushNotification
  sentence only right after the `event` field, as the last element of the
  block and at most once; anything else still makes the notification
  malformed ([issue #697](https://github.com/sakuraiyuta/kaoiro/issues/697)).
- Codex: on the app-server backend, operator steer is on by default and
  follows `in_flight_delivery.codex` and the per-agent switch. The exec
  backend still queues. `KAOIRO_CODEX_OPERATOR_STEER`,
  `KAOIRO_CODEX_OPERATOR_STEER_PERSONAS` and the wrapper config key
  `operator_steer` have no effect and print a retirement warning, also for a
  wrapper started without the runner
  ([issue #563](https://github.com/sakuraiyuta/kaoiro/issues/563)).

### Runner

- The runner warns once per process for each retired Codex operator-steer
  input, no longer relays them, and removes the two retired variables from the
  environment of the wrappers it starts
  ([issue #563](https://github.com/sakuraiyuta/kaoiro/issues/563)).

### Server deploy

- A recovery table covers every persisted phase of the server deploy
  transaction. Refusal hints, `status` and the runbook table come from it.
  A prepare stopped at `preflight` or `old_image_saved` closes by a
  record-only or non-destructive rollback; the non-destructive rollback no
  longer trips the fleet guard; one refusal names both server locks; `status`
  reports the locks it sees
  ([issue #696](https://github.com/sakuraiyuta/kaoiro/issues/696),
  [issue #584](https://github.com/sakuraiyuta/kaoiro/issues/584),
  part 2 of [issue #681](https://github.com/sakuraiyuta/kaoiro/issues/681)).

### Tests and CI

- Every suite runs under a host isolation guard, and a fast pre-gate runs
  before the full suites
  ([issue #577](https://github.com/sakuraiyuta/kaoiro/issues/577),
  [issue #578](https://github.com/sakuraiyuta/kaoiro/issues/578)).

### Decisions

- ADR-0063 records that engine delivery semantics are a measured contract,
  re-measured on every SDK bump
  ([issue #585](https://github.com/sakuraiyuta/kaoiro/issues/585)).

## Upgrading

- Update the server and the runner to the same commit.
- The release is TL: follow the canary stage in
  [High-risk change release](../operations/high-risk-change-release.md).
- If you used `KAOIRO_CODEX_OPERATOR_STEER=0` or a persona list to keep Codex
  operator steer off, use `in_flight_delivery.codex.enabled: false` (host),
  `in_flight_delivery.codex.default: false` (new agents) or the per-agent
  switch instead.

## Known issues

- The server deploy CLI still refuses an update when a
  `docker-compose.override.yaml` is present; move it aside during the
  deployment and restore it afterwards (part 1 of
  [issue #681](https://github.com/sakuraiyuta/kaoiro/issues/681)).
- Server-only `session_lifecycle` kinds are not yet rejected at the wrapper
  entry ([issue #683](https://github.com/sakuraiyuta/kaoiro/issues/683)).
- The follow-up authorization guidance and the `delivery_lost` guidance
  disagree ([issue #686](https://github.com/sakuraiyuta/kaoiro/issues/686)).
- After native continuations close, they stay closed until the wrapper
  restarts ([issue #679](https://github.com/sakuraiyuta/kaoiro/issues/679)).
