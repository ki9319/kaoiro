# Release v2026.10.28.2

- Previous production release: [v2026.10.28.1](v2026.10.28.1.md) (`5a0d8949`, server and runner)
- Range: `v2026.10.28.1..v2026.10.28.2`; the code range
  `v2026.10.28.1..f82f9c4c` has 28 commits, not counting this note
- Release class (the preparer's assessment; a reviewer makes the formal
  judgement): neither FS nor TL
  ([High-risk change release](../operations/high-risk-change-release.md)).
  No wrapper path, runner start-path module or SDK, CLI or native pin
  changes. The one path candidate is `runner/deploy/codex-state-recovery.mjs`
  (FS list). The change adds a declarative table of the service-manager calls
  of each recovery branch, a column rendered from it into the runbook, one
  branch row for a restore-staging copy fault, and a module-load check that
  the table covers the declared branches. The behaviour of the recovery
  commands is not changed. It is loaded by the Codex state helper on the
  install, switch and update path, not by the runner start or a wrapper turn;
  the load-time check depends only on the file's own data and passes at this
  commit. The check throws only if the declarations and the table disagree,
  and the shipped table loads and renders
  (`node runner/deploy/codex-state-recovery.mjs --runbook` exits 0). The
  server change adds one bundled persona pack archive and its test, with no
  code change, so the release does not need the canary stage. The server and
  the runner are still updated to the same commit, and a release of this shape
  may go through the ordinary-release steps instead of the operator's card.

## Highlights

- **New persona `anzu`** (apricot courier, intended for GPT-6 Luna peers),
  bundled with all eight states including `fatigued`
  ([issue #864](https://github.com/sakuraiyuta/kaoiro/issues/864)).
- **Status-line links are readable on the dark card.** Links in the agent
  status line, its detail panel and its change log use the theme colour in
  every state, with the underline and focus ring kept
  ([issue #853](https://github.com/sakuraiyuta/kaoiro/issues/853)).
- **The runner runbook says what each recovery branch does to the runner
  service.** The recovery table gains a Service column
  ([issue #863](https://github.com/sakuraiyuta/kaoiro/issues/863)).

## Changes

### Personas

- The bundled pack `anzu` (id `anzu`, display name あんず, CC0-1.0) is added
  in the layout of `moegi`: manifest, personality, eight sprites and a
  provenance file for each state, with the pack archive at
  `server/priv/persona-packs/anzu-1.0.0.zip`. The persona addresses the
  operator as 「依頼主さん」 and treats each request as a delivery. See
  [Character-design policy](../specs/personas.md) for the design and the
  generation record
  ([issue #864](https://github.com/sakuraiyuta/kaoiro/issues/864)).
- The two sprite post-processing scripts and a stage-by-stage checker
  (`scripts/verify-persona-sprite-chain.py`) are added with the expected
  hash of every stage. The scripts need Pillow, SciPy and NumPy at pinned
  versions; SciPy is a new dependency of these scripts only, not of the
  server, wrapper or runner. The negative controls are in the
  [sprite chain record](../evidence/personas/2026-10-28-anzu-sprite-chain.md).
- The server test now expects `anzu` among the bundled personas and checks
  its eight states, URLs and hashes against the served bytes.

### Dashboard

- Status-line links (`a`, `a:visited` and the rendered `.md-link`) take
  `--c-thinking` instead of the browser default, which was hard to read on the
  dark card. A browser test checks the contrast (at least 4.5) on the card,
  the detail panel and the change log, and the focus ring
  ([issue #853](https://github.com/sakuraiyuta/kaoiro/issues/853)).
- A test fails if the colour rule is removed, replaced by a competing one, or
  written in a form the check does not understand
  ([issue #866](https://github.com/sakuraiyuta/kaoiro/issues/866)).

### Runner

- The recovery table in `runner/deploy/codex-state-recovery.mjs` declares, for
  every branch and guard site, the ordered calls a run makes to the service
  manager (`untouched`, `stop`, `start`, `stop-start`) and the service's state
  when it begins. The runbook table is rendered from the same declarations
  with a Service column, and its legend defines outcomes on the selected record
  alone. A new row `R-RES-stage-copy` covers a copy fault while staging a
  restore. Recovery behaviour is unchanged
  ([issue #863](https://github.com/sakuraiyuta/kaoiro/issues/863),
  [Recovery table](../operations/runner-update-and-rollback.md#recovery-table)).

## Development

Test, CI and evidence changes only; none changes how the system is operated
except the job timeout noted below.

- The `test-isolation` job also runs the canonical Node test entries serially
  and fails when an entry runs no real test; its timeout is 15 minutes (from
  10). The isolation guard now covers `worker_threads` workers, and the real
  pre-gate suite (six cases) runs under it
  ([issue #856](https://github.com/sakuraiyuta/kaoiro/issues/856),
  [issue #872](https://github.com/sakuraiyuta/kaoiro/issues/872),
  [Test isolation](../contributing/test-isolation.md),
  [Pre-gate](../contributing/pre-gate.md)).
- The runner CI job's fake `systemctl` is answered by a shell front for the
  read-only queries, which was the long pole of the codex state tests. The
  measurement, the shadow run and the negative controls are recorded
  ([issue #797](https://github.com/sakuraiyuta/kaoiro/issues/797),
  [evidence](../evidence/runner-ci-time-issue-797-2026-10-28.md)).
- The recovery table's service calls are pinned by tests, and the digest of
  the state fixture is keyed by whole path, so two names that share a prefix
  up to a space no longer collapse
  ([issue #863](https://github.com/sakuraiyuta/kaoiro/issues/863)).
- The Grok host test releases fixture progress only after the host is waiting
  for a permission, so log chunks that coalesce no longer flake it
  ([issue #892](https://github.com/sakuraiyuta/kaoiro/issues/892)).

## Operator steps

- **Update the server and the runner to the same commit.** Follow the
  release steps for the class above; the preparer's assessment is that the
  card and the canary stage are not required, and the reviewer's judgement
  decides.
- **No configuration change.** No new environment variable, runner
  capability or native pin.
- **The new persona appears after the server update.** Launch an agent with
  `anzu` to use it. A host that provides its own persona directory
  (`KAOIRO_PERSONA_DIR`) and keeps packs there should copy the new pack to
  it as it does for other packs; the bundled archive alone serves a host
  that does not.
- **Rolling back** to v2026.10.28.1 removes the bundled `anzu` pack; a host
  that copied it into its own persona directory removes it there too. It also
  restores the previous link colour and runbook; an agent already launched
  as `anzu` needs a different persona afterwards. No data format changes.
