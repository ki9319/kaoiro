# Release v2026.10.17.1

- Deployed: 2026-10-17 (server and runner)
- Commit: `e9068690e93d1fb2bbc5bf4e3819a4f5d08332a1`
- Previous production release: [v2026.10.15.22](v2026.10.15.22.md) (`fed60d78`, server and runner)
- Range: `v2026.10.15.22..v2026.10.17.1`, 26 commits
- Release class: TL (the Claude Code wrapper's host and CLI). The server code
  is unchanged; the server was updated to keep the same commit as the runner.

## Highlights

- A Claude Code peer can now call `send_to_agent` from a turn started by a
  background Agent hand-back, a Monitor notification or a `run_in_background`
  Bash completion
  ([issue #426](https://github.com/sakuraiyuta/kaoiro/issues/426),
  [issue #674](https://github.com/sakuraiyuta/kaoiro/issues/674)).

## Changes

### Claude Code

- Native continuation ownership is on by default. The wrapper marks each
  subagent, Monitor and background-task launch, proves a returning
  notification against that mark and the CLI transcript, and admits the
  reply as a reply to the request that started the launch
  ([ADR-0063](../adr/0063-layered-delivery-authority-and-continuations.md)).
- `KAOIRO_CLAUDE_NATIVE_CONTINUATIONS`: unset or `1` turns it on, `0` turns it
  off, and any other value turns it on with a startup warning.
- If native evidence fails while no lease is held, only native continuations
  close, for the rest of the wrapper's lifetime, with a warning; the peer keeps
  running. A failure while a lease is held still stops the host.

### Scripts

- `scripts/dev.sh` and `scripts/dogfood.sh` build the Grok Build wrapper
  package ([issue #678](https://github.com/sakuraiyuta/kaoiro/issues/678)).

## Upgrading

- No configuration change. To keep the previous behavior, set
  `KAOIRO_CLAUDE_NATIVE_CONTINUATIONS=0` for Claude Code peers.
- Update the server and the runner to the same commit.
- The release is TL: follow the canary stage in
  [High-risk change release](../operations/high-risk-change-release.md).

## Known issues

- After native continuations close, they stay closed until the wrapper
  restarts ([issue #679](https://github.com/sakuraiyuta/kaoiro/issues/679)).
- The acceptance runs left some paths unmeasured (Agent interrupt survival,
  batched completions at the product entry, Monitor deny); see the ADR-0063
  amendment of 2026-10-17.
- The server deploy CLI builds its recovery plan from the old compose file
  alone, so a deployment that adds a `docker-compose.override.yaml` is
  refused as a project identity change
  ([issue #681](https://github.com/sakuraiyuta/kaoiro/issues/681)).
