# Release v2026.10.14.13

- Deployed: 2026-10-14
- Commit: `6e7f7b7b9c26f76bf7d5515e10853dd4d1414149`
- Previous production release: v2026.10.10.2 (`64aa00ae`)
- Range: `v2026.10.10.2..v2026.10.14.13`, 38 commits
- Release class: TL plus a runner change (new engine capability); see
  [High-risk change release](../operations/high-risk-change-release.md)

## Highlights

Grok Build joins Claude Code, Codex and Antigravity as the fourth engine.
The runner hosts the Grok CLI as a resident ACP agent; the kaoiro tools reach
it over an authenticated loopback HTTP MCP server, and permission switches
are applied at turn boundaries. Engine contract:
[Grok ACP](../reference/engines/grok-acp.md).

## Changes

### Grok Build engine

- Registration, launch and a minimal resident ACP host (work unit 1, #590).
  The launch catalog offers only the account default model.
- Vendor extensions are kept out of the shared ACP client module (#597).
- The kaoiro tools are served over an HTTP MCP server on the loopback
  interface with a bearer token generated for each tool host, replacing the
  stdio bridge that a read-only sandbox blocked (#604). Startup waits for an
  authenticated tool listing and fails closed.
- Permission and sandbox switching across resident session generations
  (work unit 2, #591). On Linux, read-only, workspace-write with network on
  and danger-full-access are accepted; workspace-write with network off is
  rejected, and a switch cannot widen beyond the launch settings. Off Linux
  only danger-full-access is accepted. When a switch fails before it
  applies, the agent stops dispatching until the server supplies the next
  selection, and the dashboard shows the stop.

Not yet supported on Grok: cold resume and history replay (work unit 3,
#592), context usage and live model and effort switching (work unit 4,
#593), and attachments, quota reporting and early delivery to a running turn
(no work unit assigned yet).

### Claude Code

- A Bash command moved to the background by timeout, or a Workflow
  notification, no longer leaves the next `send_to_agent` unbound (#595).

### Dashboard

- A permission gate stop is shown for any engine, with its reason; the stop
  is explained even where no switch action is available (#612).
- The offline agent list scrolls when the details pane has its own scroll
  box (#545).
- Deeply nested chat markdown is shown as escaped text instead of throwing
  (#502).

### Deploy

- Server deploy parses tar listings under `LC_ALL=C`, so it no longer fails
  under a non-English locale such as `ja_JP.UTF-8` (#552). Before it stops or
  restores anything, rollback preflight refuses a manifest whose recorded
  non-ASCII entry names differ from the `LC_ALL=C` listing, for example one
  recorded under a UTF-8 locale before this change.

### Tests

- The Antigravity interrupt-queue composition test waits for fixture epoch
  closure and passes under the full wrapper fan-out (#598).

## Upgrading

- To use Grok, add `grok` to the runner's `capabilities` and put the Grok CLI
  on `PATH`; see
  [Grok runner configuration](../reference/configuration/runner.md#grok-runner-configuration).
  Runners without `grok` are unaffected.

## Known issues

- Each streamed Grok text chunk becomes its own assistant message in the
  dashboard, and an inter-agent turn shows its wrapped prompt as a user
  message (#621).
- Grok `result.text` has no size cap and a very long reply can exceed the
  envelope limit (#622).
- Grok emits one `state_change` envelope per streamed chunk (#623).
- `clipText` can exceed its byte cap by 2 bytes when the cut splits a UTF-8
  character (#624).
