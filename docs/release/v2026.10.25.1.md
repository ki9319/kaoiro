# Release v2026.10.25.1

- Deployed: 2026-10-25 (server and runner)
- Previous production release: [v2026.10.24.1](v2026.10.24.1.md) (`d0c43ed3`, server and runner)
- Range: `v2026.10.24.1..v2026.10.25.1`
- Release class: FS. The range changes the runner's install, switch, update
  and native Codex state helpers, which sit on the path that starts the
  runner and keeps it up
  ([High-risk change release](../operations/high-risk-change-release.md)).
  No wrapper turn path, SDK, CLI or native pin changed. The server change is
  a dependency update and a new transport test.

## Highlights

- **Minimized native Codex state** (issue 709 N2). The runner keeps one small
  v2 record per state-aware operation instead of the earlier phase machine.
  Acceptance, receipts, lineage, legacy records, barriers and `abandon` are
  retired
  ([issue #709](https://github.com/sakuraiyuta/kaoiro/issues/709)).
- **Recovery hints from one table** (issue 709 N3). Every Codex state refusal
  names its record and prints the next command from a single recovery table;
  `kaoiro-runner-codex-state.mjs next` prints the hint without acting
  ([issue #709](https://github.com/sakuraiyuta/kaoiro/issues/709)).
- **Security dependency updates.** Server Bandit 1.13.1 (with hpax 1.1.0,
  plug_crypto 2.2.1 and Thousand Island 1.6.0) and `@xmldom/xmldom` 0.9.12
  ([issue #701](https://github.com/sakuraiyuta/kaoiro/issues/701)).

## Changes

### Runner

- Native Codex state: minimized v2 records and phase machine; the helper's
  child processes get a closed environment
  ([issue #709](https://github.com/sakuraiyuta/kaoiro/issues/709)).
- Codex recovery hints rendered from one recovery table; a refusal before the
  stop leaves records and the service unchanged
  ([issue #709](https://github.com/sakuraiyuta/kaoiro/issues/709)).
- The build format is checked before a state-aware Codex record is published,
  so a format refusal leaves no record
  ([issue #769](https://github.com/sakuraiyuta/kaoiro/issues/769)).
- `with-build-identity` names a child environment it cannot build
  ([issue #712](https://github.com/sakuraiyuta/kaoiro/issues/712)).

### Release and deploy

- Landing allocation, production release publication, the completion
  collector and the enrollment gates are retired. The release operator
  creates one release tag per production release, and the note lands before
  the tag
  ([issue #709](https://github.com/sakuraiyuta/kaoiro/issues/709),
  [issue #754](https://github.com/sakuraiyuta/kaoiro/issues/754)).

### Server

- Bandit 1.13.1 rejects an HTTP/1 request whose absolute-form authority does
  not match; HTTP/2 stays disabled
  ([issue #701](https://github.com/sakuraiyuta/kaoiro/issues/701)).

### Dashboard

- Protocol types are imported by package name
  ([issue #688](https://github.com/sakuraiyuta/kaoiro/issues/688)).

### Development

  ([issue #526](https://github.com/sakuraiyuta/kaoiro/issues/526)); test

  ([issue #749](https://github.com/sakuraiyuta/kaoiro/issues/749),
  [issue #752](https://github.com/sakuraiyuta/kaoiro/issues/752),
  [issue #748](https://github.com/sakuraiyuta/kaoiro/issues/748),

  ([issue #586](https://github.com/sakuraiyuta/kaoiro/issues/586)).

## Operator steps

- Release class FS: the operator runs the high-risk release with the start
  gate and the canary.
- Native Codex state cutover (N2): before the first activation of this
  release, every schema-1 transaction must be `completed`, `restored` or
  `retired`, and every schema-1 backup retired; there is no conversion. The
  first activation must keep the same native Codex binary. A same-native,
  code-only update needs no `--codex-home` or backup options
  ([Runner update and rollback](../operations/runner-update-and-rollback.md)).
- Run the release from the candidate's own deploy helpers. Release-specific
  flags of the retired publication path now fail as unknown arguments.
- Rollback to `v2026.10.24.1` is available only while no v2 operation is
  unfinished and no v2 snapshot is retained.

## Known issues

  cleanup `ENOTEMPTY` and passed on re-run
  ([issue #787](https://github.com/sakuraiyuta/kaoiro/issues/787)).
- Antigravity peers on Gemini 4 Argon show the Flash/Pro rate-limit buckets,
  and an Argon quota error is reported as `api_error`
  ([issue #788](https://github.com/sakuraiyuta/kaoiro/issues/788)).
