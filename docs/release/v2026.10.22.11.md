# Release v2026.10.22.11

- Deployed: 2026-10-23 (server and runner)
- Commit: `b7a31e4227f127ea8ba8913ccc19fd2e7b117132`
- Previous production release: [v2026.10.21.1](v2026.10.21.1.md) (`3eaf5c99`, server and runner)
- Range: `v2026.10.21.1..v2026.10.22.11`, 37 commits
- Release class: FS (the runner and deploy start path and
  `scripts/build-identity.mjs` changed). The server's Elixir code, the
  wrappers and the dashboard are unchanged.

## Highlights

- The server deploy CLI records `server/docker-compose.override.yaml` in the
  transaction and uses the same Compose files for the update and for every
  recovery path. The override no longer has to be moved aside during a
  deployment (part 1 of
  [issue #681](https://github.com/sakuraiyuta/kaoiro/issues/681)).
- Build identity reads schema-2 release tags as well as the existing landing
  tags (P1 of [issue #709](https://github.com/sakuraiyuta/kaoiro/issues/709)).
  Landing tags are still created on every develop landing until cutover C3.

## Changes

### Server deploy

- Compose override files are bound to the update and recovery plans; resumed
  inputs are validated before any Compose container lookup, and plan hashes
  are type-checked
  ([issue #681](https://github.com/sakuraiyuta/kaoiro/issues/681)).
- Child processes started by the deploy CLI, including the archive listing,
  receive a prepared environment instead of the caller's whole environment
  ([issue #711](https://github.com/sakuraiyuta/kaoiro/issues/711),
  [issue #713](https://github.com/sakuraiyuta/kaoiro/issues/713)).

### Build identity

- `scripts/build-identity.mjs` accepts schema-2 release tags and names them
  in the update preflight refusal; the identity formats reported by the
  server health endpoint are unchanged
  ([issue #709](https://github.com/sakuraiyuta/kaoiro/issues/709)).

### Runner

- The native Codex state protection no longer inspects other users' state
  or prints migration diagnostics; the cgroup v2 preflight is kept (N1 of
  [issue #709](https://github.com/sakuraiyuta/kaoiro/issues/709)).

### Tests and CI

- The test-isolation job observes the real repository once per CI candidate
  ([issue #705](https://github.com/sakuraiyuta/kaoiro/issues/705)).

## Upgrading

- Update the server and the runner to the same commit.
- Do not move `server/docker-compose.override.yaml` aside; the deploy CLI
  now records it.
- The release is FS: run the production-shape start gate and the canary
  stage in
  [High-risk change release](../operations/high-risk-change-release.md).
