# Release v2026.10.18.1

- Deployed: 2026-10-18 (server and runner)
- Commit: `69b35ffd34fb9a524a45151215bf4925fa19a37c`
- Previous production release: [v2026.10.17.1](v2026.10.17.1.md) (`e9068690`, server and runner)
- Range: `v2026.10.17.1..v2026.10.18.1`, 28 commits
- Release class: TL (the wrapper CLIs, the wrapper transport and the
  inter-agent send path change). The runner start path is unchanged.

## Highlights

- A director can reset the session of the peer assigned to its work with the
  new `request_peer_session_reset` tool, instead of asking the peer by
  message ([issue #677](https://github.com/sakuraiyuta/kaoiro/issues/677),
  [ADR-0068](../adr/0068-director-requested-peer-session-reset.md)).
- The operator can open an agent's session lifecycle history from the agent
  detail view, including who requested each reset
  ([issue #682](https://github.com/sakuraiyuta/kaoiro/issues/682)).

## Changes

### Server

- Director-requested peer session reset. The server accepts the request only
  when the named work is `active` (assigned and accepted), the requester is
  its director, the target is its assignee and the authority epoch matches.
  Every authority failure answers `reset_not_authorized`. The target goes
  through the same gates as an operator reset, and the result returns to the
  requester ([issue #677](https://github.com/sakuraiyuta/kaoiro/issues/677)).
- The session lifecycle query tells an unavailable lifecycle store apart from
  an empty history, and a director-requested reset carries the title of its
  work ([issue #682](https://github.com/sakuraiyuta/kaoiro/issues/682)).

### Wrappers

- `request_peer_session_reset` is registered for Claude Code, Codex and
  Antigravity peers. Its result carries `agent_id`, `mode` and `work_id`
  ([issue #677](https://github.com/sakuraiyuta/kaoiro/issues/677)).
- A refusal with `session_reset_pending` no longer promises a later result
  ([issue #677](https://github.com/sakuraiyuta/kaoiro/issues/677)).
- After a peer replies through inline recovery, a follow-up send in the same
  turn is authorized instead of being rejected as `stale_reply_basis`
  ([issue #684](https://github.com/sakuraiyuta/kaoiro/issues/684)).

### Dashboard

- A session reset started by a director shows the director and the work
  while it runs
  ([issue #677](https://github.com/sakuraiyuta/kaoiro/issues/677)).
- Operator-only session history in the agent detail view. It lists lifecycle
  events newest first, shows requester role, requester and work for
  director-requested resets, refreshes when a reset starts or completes, and
  says so when the history cannot be read
  ([issue #682](https://github.com/sakuraiyuta/kaoiro/issues/682)).

### CI

- A check keeps the server's peer reset reply vocabulary in step with the
  wrapper's ([issue #677](https://github.com/sakuraiyuta/kaoiro/issues/677)).

## Upgrading

- No configuration change.
- Update the server and the runner to the same commit.
- The release is TL: follow the canary stage in
  [High-risk change release](../operations/high-risk-change-release.md).
- A director can reset a peer only after the peer has accepted the work.
  While the work is only nominated, the request answers
  `reset_not_authorized`.

## Known issues

- The server deploy CLI still refuses an update when a
  `docker-compose.override.yaml` is present; move it aside during the
  deployment and restore it afterwards
  ([issue #681](https://github.com/sakuraiyuta/kaoiro/issues/681)).
- Server-only `session_lifecycle` kinds are not yet rejected at the wrapper
  entry ([issue #683](https://github.com/sakuraiyuta/kaoiro/issues/683)).
- The follow-up authorization guidance and the `delivery_lost` guidance
  disagree ([issue #686](https://github.com/sakuraiyuta/kaoiro/issues/686)).
- After native continuations close, they stay closed until the wrapper
  restarts ([issue #679](https://github.com/sakuraiyuta/kaoiro/issues/679)).
