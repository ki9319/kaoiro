# Grok Build ACP premises

Version boundary: Grok Build 1.0.52; ACP SDK 1.8.0. These results summarize
pre-implementation probes recorded for [issue 589](https://github.com/sakuraiyuta/kaoiro/issues/589).
They describe measured cases, not every permission policy or platform.
Raw records stay private. No user rules or machine-specific values are included.

| Premise | Observation | Limit |
| --- | --- | --- |
| ACP initialization | initialize and session/new succeed using an existing login | Does not prove authentication bootstrap |
| Resident session | Two prompts share one session; cancel returns cancelled | Cold resume deferred |
| MCP bridge | An injected stdio server handles tools/list and tools/call | Production ToolHost round trip is checked separately |
| Rules | session/new _meta.rules affects replies | session/load retained original rules |
| Permission import | Inspect reports inherited Claude permission sources | No compat switch for that import |
| Denial | Literal command-text matching can block before execution | Runtime-constructed paths were not matched |
| Classifier | Some denials return to the model without a client permission request | Escalation thresholds in older source remain unmeasured |
| Broker escalation | request_permission offers allow/reject options; reject leaves no target file | Policy-dependent, not every call escalates |
| Hooks | Configuration enables Claude hooks; disabled configuration suppresses them | Individual hook compatibility is separate |
| Cancellation | cancellationCategory distinguishes MidTurnAbort from PermissionRejected | cancel stopReason alone is insufficient; an active shell child can survive cancel |
| Prompt identity | Prompt response metadata correlates with vendor turn completion | MCP tools/call lacks turn identity |
| SDK validation | Unknown update variants are dropped and SDK diagnostics can include raw messages | Wrapper filters diagnostics and tests the same stream |
| Usage | ACP does not expose account quota limits | Context/model controls deferred |

## Linux sandbox probes

| Profile | Outside-cwd write | Inside-cwd write | Child network |
| --- | --- | --- | --- |
| workspace | denied | allowed | allowed |
| read-only | denied | denied outside always-writable directories | hostname resolution failed |
| off | allowed | allowed | allowed |

Seccomp state was observed inside the tool process; Landlock is inferred
from permission-denied writes and the bundled sandbox guide. Read-only has
a stronger network claim than a DNS failure proves; the production-entry
acceptance includes a literal-address connection control. The sandbox guide
states that macOS network restriction is a no-op. No macOS OS-sandbox pair
is accepted by work unit 1, pending platform measurements.

Temporary directories and Grok state remain writable under these profiles,
subject to protection of direct settings and hook paths. Read-only
must not run with cwd in those writable roots.

## Implementation evidence

Native acceptance is opt-in with KAOIRO_LIVE_GROK=1 through runGrokCli,
using the production host, brokers and stdio bridge. Private run artifacts
identify the tested commit and report exit codes, observed state changes,
metadata and negative controls. Fixture tests cover parser failure, unsupported
operations, missing binaries, child exit and bounded shutdown. Do not treat
fixture results as evidence of a vendor's OS enforcement.

The production-entry Linux cases also test a literal loopback address: both
hostname and literal-address child connections are denied in read-only and
allowed in workspace and off. They measure actual file existence and a
fixture listener, as well as the tool script's report.

For Grok Build 1.0.52, cancellation returned `cancelled` while the known
shell child remained alive after five seconds. Closing Grok removed that
same child. These are separate premises; SIGTERM cleanup is not evidence
that `session/cancel` terminates a tool. Native acceptance asserts the
observed survival, and checks active-child cleanup on wrapper SIGTERM.
